# 本地开发收尾交接

本文档用于指导下一轮 agent 完成本地收尾和用户已确认的交互修复。执行时保持现有架构、中文注释/提示和 vanilla ES Modules 约束，不做无关重构。

## 已确认问题

1. 健康聊天的可选槽位在 `frontend/assets/js/pages/chat.js` 中直接显示内部字段名，可能出现 `mood`、`cuisine`、`convenience` 等英文。
2. `HealthInputNormalizer` 和 `FixtureAgentInvoker` 对口语化餐食偏好覆盖不足，至少要识别“尽快能吃上”“便利店能买的速食”“胃口不好”“想吃素”“酸甜口味”等表达，并尽量在一条消息中合并多个槽位。
3. 生产计划页 `frontend/assets/js/pages/plans.js` 的计划名称目前直接渲染为输入框，没有独立的点击编辑、保存、取消状态。
4. 计划页空日期同时显示“暂无安排 · 新增”和“添加项目”两个入口，应只保留一个“添加项目”。
5. 计划库长名称需在桌面和移动端稳定省略，不得溢出侧栏或挤压其他内容。

## 实施要求

### 聊天识别与文案

- 建立统一的中文槽位显示映射，`optionalSlots`、`missingSlots`、已确认摘要都不得暴露内部英文键。
- 中文文案应面向普通用户，例如：心情、用餐场景、菜系或食材、口味、能接受的耗时和购买方式。
- 扩充确定性归一化别名，并让模型输出、确定性路径和 fixture 降级路径共享归一化规则。
- 至少覆盖：快速/尽快/马上能吃/赶时间/便利店/速食/外带、没胃口/胃口不好、素食/吃素、酸甜等表达。
- 一次用户消息可能包含多个条件，必须全部收集并合并；不要要求用户按照字段名或固定格式重复输入。
- 保留否定安全和领域隔离，不要把历史餐食槽位污染到动作/作息领域。

### 计划名称编辑

- 可编辑计划进入页面时先显示标题文本；点击标题后进入编辑态。
- 编辑态的输入框最右侧显示“保存”和“取消”两个按钮。
- 保存按钮只提交名称修改，或明确复用现有批量保存 API，但必须保持项目编辑状态和 dirty 状态语义一致。
- 取消按钮恢复原名称并退出编辑态。
- 有改动但未点击保存/取消时，点击其他区域、切换计划、刷新或取消项目编辑不得静默保存；应按现有未保存确认机制处理。
- 名称不能为空，最大长度保持服务端 128 字符限制；保存失败时保留用户输入并显示中文错误。

### 空日期与长名称

- 空日期只保留一个“添加项目”入口，继续使用现有资源选择弹窗。
- 计划库文本容器必须具备稳定的 flex/grid 约束（包括必要的 `min-width: 0`），超长名称使用省略号。
- 用真实浏览器验证至少一个超长中文名称和至少一个空日期计划；检查桌面 `1710×983` 与移动端视口无横向溢出。
