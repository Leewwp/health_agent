# 计划上下文、训练多样性与资源选择器详情边界

Status: accepted

> 计划简报的用户确认语义已由 [ADR-0016](0016-explicit-health-task-routing-and-plan-preflight.md) 取代：本 ADR 中“重新确认”指旧版本行为，现行流程使用“开始生成/补充”预览，不保留独立确认步骤。

本次交互修复采用以下产品语义：健身单次动作推荐必须完成训练目标、训练部位、器械和难度四项澄清后才允许检索或推荐；训练计划不把训练部位连续性作为阻断规则，用户指定的训练日和部位优先，“全身”也可连续安排。候选动作足以覆盖训练日时，一周内动作应尽量且确定性地全局不重复；候选不足时允许复用唯一可行动作。用户进入计划上下文后，能够解释为计划字段的输入优先修改当前计划简报并重新展示开始生成入口，只有明确的新任务指示才切换到餐食或动作推荐流程。

计划编辑中的“替换资源”和“新增项目”使用独立资源选择器详情弹窗，不复用计划项目详情抽屉。弹窗只负责浏览，不提供“选择此资源”操作；用户关闭详情后在选择器中自行选择。弹窗必须高于选择器显示并拥有独立滚动，支持关闭按钮、点击外部遮罩和键盘 `Esc` 退出，关闭后保留选择器的品类标签、筛选条件、页码和滚动状态；替换餐食/动作分别默认打开对应品类标签，新增项目统一默认打开餐食标签。

这些边界分别解决了澄清阶段过早空结果、全身训练被错误连续性规则拒绝、计划修改丢失会话上下文、动作候选重复，以及详情层级互相覆盖的问题。代价是推荐路由、计划生成校验与前端弹层必须明确区分“当前任务上下文”和“资源浏览详情”，不能再用单一最低槽位或全局详情抽屉隐式兜底。

综合计划的简报收集采用有序阶段：默认先餐食、后训练；用户可以交错补充，系统合并共享目标等字段但保持当前阶段追问连续。两个子简报分别完整后显示“开始生成”，服务端在生成时重新校验当前简报，不保留独立确认状态。详情接口存在时只显示完整详情；动作有拆分步骤时隐藏重复的整段讲解，媒体依据实际资源选择。资源库详情抽屉继续提供收藏/减少推荐，picker 详情仅保留收藏。计划时间接受秒为 `00` 的 `HH:mm:ss` 并归一化，非零秒拒绝。
