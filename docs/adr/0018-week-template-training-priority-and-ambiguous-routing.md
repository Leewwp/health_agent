# 周模板、训练优先调度与歧义任务仲裁

Status: accepted
Supersedes: ADR-0014 (only the meal/training generation order and conflict adaptation rule)

健康 Agent 的周计划是供参考且不会过期的七天模板。对话不再要求或展示“目标周”；服务端使用生成当天所在周的周一作为不可见内部锚点，计划页面仍展示周一至周日及每天的具体安排。保留现有日期字段和周范围存储，是为了避免破坏计划编辑、版本和历史 API，同时把日期从用户需求语义中移除。

## 周模板与目标周

内部周锚点不是用户简报字段：`weekStart` 从简报必填条件中移除，完整性、缺失项、提问和摘要均不再包含目标周，也不得再出现“请给目标周的周一日期”等追问。新生成在生成边界按“生成当天所在周的周一”统一派生，三个生成入口（餐食、训练、综合）与编排层共用同一派生规则；旧会话 JSON 缺失锚点时按同一规则补齐，已有锚点则保持不变（包括幂等重放），不得因为当前日期或用户消息日期而静默改写。计划不因现实日期经过而过期。

用户继续输入具体日期（如“改成 2026-09-07”“下周安排”）时，不改变计划语义或简报字段；系统可简洁说明计划按周一至周日参考安排、不需要指定日期。对话中出现的日期一律不写入简报，任何解析器都不得把用户日期悄悄改写为内部锚点。聊天摘要和回复不展示内部日期；计划页面仍正常显示周一至周日及每天的具体安排。

## 训练优先的餐训时间适配

综合计划中用户指定的训练日期和时间是硬约束，餐食时间是可调整安排。组合器先使用早餐 08:00、午餐 12:00、晚餐 18:00 的默认窗口，默认时长保持早餐 30 分钟、午餐与晚餐 60 分钟。发生冲突时按确定性顺序尝试：先训练结束后立即开始用餐（不强制增加 30 分钟间隔），再训练开始前倒推相同餐食时长；同一天多次训练按时间顺序逐一避让。餐食允许移出默认窗口但不得跨午夜，当日可行调度边界按本地 `05:00-24:00` 定义；训练和餐食仍不得重叠，相邻区间按 `[startTime,endTime)` 定义视为合法。两侧均无可行时段时返回稳定错误，综合计划整体失败并回滚，不允许静默重叠。时间适配成功不视为计划冲突，也不得触发误导性的窗口/重叠告警；成功适配应在生成说明、metadata 与 Trace 中记录被移动的餐次以及移动到训练前还是训练后。

该决策替换 ADR-0014 中“先固定餐食、冲突即拒绝”的生成时序，但保留最终 Guard、半小时粒度和时间区间校验。

## 计划上下文优先路由

计划上下文优先于泛化领域启发式：在活动的计划简报中，“训练时间/训练时段 + 修改表达（改为、调整为、改成、安排到等）”必须进入训练简报字段修改，而不是作息域；“什么时候训练合适”“训练时段建议”“晚上几点后停止锻炼”“几点睡”等事实或建议问题才进入作息域。已生成计划收到字段修改时重新打开对应简报并生成新的草稿，不直接修改已保存计划。裸“餐食计划”等无法区分新建与修改的短句，必须澄清是修改当前计划还是新建一份，不由模型猜测。

## 确定性路由与歧义仲裁

路由采用确定性规则优先、歧义仲裁兜底的两层模型。快捷问题及其同义表达、明确新建/修改/推荐/作息证据可以确定性直接路由；快捷问题关键词只是候选入口之一，不得作为唯一自然语言入口，否则换一种说法会被错误降级。只有规则冲突、多个任务候选或置信度不足时才调用一次轻量意图仲裁 Agent；Agent 只返回受限候选意图、领域、置信度和证据，不能覆盖当前计划上下文、风险规则、资源资格或 Java 最终路由。Agent 失败、低置信度或无法解释时必须澄清，不得猜测执行或随意回退到推荐。Trace 需要记录确定性证据、Agent 仲裁来源和最终裁决原因，防止再次出现无关输入触发错误任务。

## 需求输入指引动态化

“需求输入指引 / 还可以补充”不是固定文本：所有餐食、综合与训练简报分支统一基于当前结构化简报计算可补充项。已填写的支持项不再重复提示，全部可选项填满后不再显示“还可以补充”；用户填了词表外的未支持值（如“中餐”）时，系统记录该偏好但不把它当作可筛选项，单独说明“已记录，暂不按它筛选”，并继续提示受支持的可选菜系。不得把“未支持”误当成“已选择可筛选项”，也不得保留独立于结构化简报的固定指引文案。

## 对既有规格的替代范围

除 ADR-0014 外，本决策废止以下既有条款的用户侧语义：

- `conversation-contracts` US 18“餐食计划默认当前周但可修改目标周”中的目标周修改部分；
- `plan-interaction-fixes`“两侧再次均完整且周起始日一致”中的用户周起始日输入要求（内部等价保留：同一计划生成时三个入口共用同一派生锚点）；
- `brief-supplement-loop` 中作息逃生口优先级高于计划上下文字段捕获的条款，作息启发式只在非计划修改输入时生效。

旧“supplementable 可补充项随填写消失”契约（meal-facet-repair）继续有效并纳入动态指引。

## Alternatives considered

- 保留目标周输入与确认：周计划是参考模板、不随时间过期，目标周确认对用户无价值，且日期字段会错误暗示时效。
- 仅删除冲突错误文案或放宽时间 Guard：掩盖问题而非解决，用户明确要求训练时间硬约束下由餐食适配，同时不允许静默重叠。
- 为“训练时间改为…”追加关键词例外清单：历史上多份漂移关键词清单已多次引发路由回归（“强制绑定关联词”未能阻止 Router 先返回 ROUTINE escape），必须改为“计划上下文 + 可解析字段修改”的结构化条件。
- 让模型在歧义时自行猜测新建/修改：无约束猜测可能改写或污染已保存计划，必须显式澄清。
- 保留固定需求输入指引：已填条件仍被提示会造成误导，必须基于结构化简报动态计算。

## 实现约束与验证

- `weekStart` 改为可选：`PlanBrief`/`MealPlanBrief` 的 `isComplete`/`missing`/`question`/`summary` 不再把目标周列为必填；三个生成服务与编排层统一在生成时派生当天所在周的周一；`DraftPlanRequest` 中“缺省为下周一”的注释与实现不符，实现时以派生规则为准并修正注释；旧会话 JSON 缺失的锚点按同一规则补齐，已有锚点保持不变，幂等重放复用原计划日期。
- 日期解析器不得改写内部锚点；对话日期输入只触发说明文案（见“周模板与目标周”）。
- 餐食适配为确定性规则，训练窗口优先、默认窗口优先、训练后立即用餐、其次训练前倒推；同日多训练按时间顺序逐一避让；`05:00-24:00` 本地边界；不跨午夜。最终校验仍由 Guard 统一执行：重叠（相邻合法）、半小时粒度、周范围、跨午夜、资源资格与风险。
- 问题 4 的路由优先级必须是“计划上下文存在 + 字段修改可解析”的结构化条件，不得再增加关键词例外；真作息问题（“什么时候训练合适”“晚上几点后停止锻炼”）回归仍进 ROUTINE。
- 仲裁 Agent 保持单次轻量调用，结果必须经过领域/任务合法性、置信度、当前会话状态与风险复核；Agent 失败或低置信时保留规则已抽取的槽位并澄清，不重复模型调用（`relevantSlotOptions` 的二次 `fastPath` 求值不得引入额外模型调用）。
- `HealthBriefRouter` 当前由调用方直接 `new` 构造；若为仲裁引入依赖，需统一构造方式，避免测试与生产实例行为不一致。
- 端到端回归必须覆盖：完整综合计划 →“训练时间改为下午五到六点”→ `COMPOSITE + PLAN`、训练时间更新、餐食简报不变、生成入口重新出现；真作息问句仍返回 `ROUTINE + RECOMMEND` 且只展示作息事实；动态指引（已填菜系不再提示、未支持“中餐”单独说明、全部填满后无“还可以补充”）；餐食适配（多训练同日、`05:00`/`24:00` 边界、跨午夜拒绝、相邻区间合法、整体回滚）。

这组决策的代价是需要同时调整简报完整性和文案、内部周锚点派生、餐训时间适配器、计划校验测试，以及共享路由和歧义仲裁测试；现阶段先固化规格，生产实现按 P0/P1 分批实施。
