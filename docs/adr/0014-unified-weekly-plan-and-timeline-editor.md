# 统一综合周计划与时间网格编辑器

Status: accepted
Supersedes: ADR-0012, ADR-0013

健康 Agent 将用户可见的每一份周计划统一建模为可包含餐食和训练项目的综合周计划；餐食-only 与训练-only 只是项目集合不同，不再作为用户侧计划类型。数据库和 API 全量采用 `DRAFT`、`UNENABLED`、`ENABLED`、`HISTORY`，旧 `ACTIVE`/`ARCHIVED` 数据在本地迁移中按外键顺序删除，不提供兼容兜底。同一用户同时只有一份 `ENABLED`，切换启用只让旧计划回到 `UNENABLED`，停用后才允许将其转为 `HISTORY`。

`ENABLED` 状态就是用户级当前启用真相，聊天按当前请求领域从这份计划读取当天对应项目。计划调整通过副本或未启用计划完成，支持审核资源的新增、替换、删除，以及半小时粒度的日期/时间移动和确定性训练参数调整；餐食和训练项目时间均不得重叠，跨午夜和跨周拒绝。移动端支持选择项目后点击目标时间格，桌面拖拽吸附作为后续专项体验。生成时先按固定餐次窗口放置餐食，再在用户指定训练日期和时间窗口内寻找不冲突的训练时段；没有可用时段时显式失败，不静默改写用户约束。

选择这一模型是为了让日常、减脂、增肌等多份计划可以并存并快速切换，同时让餐食、训练和综合计划共享一套详情、启用和编辑流程。代价是需要废弃现有按 `MEAL`/`EXERCISE` 分离的当前安排关系、移除启用新计划即归档旧计划的约束，并增加计划项目增删改、时间冲突校验和响应式时间编辑器。

> 部分替代说明：ADR-0018 仅替代本 ADR 上述“生成时先固定餐食窗口、训练无可用时段即失败”的生成时序。综合生成现在必须先满足用户训练时间，再由确定性餐训适配器调整餐食；本 ADR 保留的最终时间轴 Guard 仍适用于适配完成后的真实重叠、跨午夜、跨周和粒度校验。

## 实现约束

- V17 仅作为本地过渡迁移建立旧的 scope 级 ACTIVE/current-assignment 结构；V18 在确认外键关系后按项目、版本、计划顺序清理旧 `ACTIVE`/`ARCHIVED` 计划数据，删除过渡表和 scope 级唯一键，再建立四态 CHECK、用户级 `ENABLED` 生成列唯一键、计划名称和写请求幂等表；V19 同步运行库状态列注释。新实现不兼容旧状态值，也不重新引入独立 current-assignment 语义。
- 计划写 API 为 `confirm`、`enable`、`disable`、`archive`、`copy` 和 `PUT /items`。写请求检查用户归属、当前状态、`expectedVersion`、`requestId` 幂等性、风险规则、资源资格、周范围、半小时粒度和时间重叠；失败在事务边界内整体回滚并返回稳定错误码。
- 餐食与训练共享同一时间轴，使用左闭右开 `[startTime,endTime)`；开始时间必须早于结束时间，分钟只能是 `00` 或 `30`，跨午夜、跨周和重叠均拒绝，相邻区间允许保存。餐食-only、训练-only 和综合计划均保存为 `COMPOSITE` 计划，只由项目集合区分。

## 验证与延期

核心自动化验证覆盖四态转换、用户级 `ENABLED` 唯一性、启用切换将旧计划置为 `UNENABLED`、停用后转历史、越权/版本/幂等、失败写入回滚、餐食训练冲突、非半小时、跨周和跨午夜拒绝。真实浏览器已在 `http://localhost:8090/#/chat` 与 `http://localhost:8090/#/plans` 完成桌面 `1710×983` 的生成、确认、启用、停用、历史转换和名称保存，以及移动 `390×844` 的确认/启用与无横向溢出检查。

计划名称、资源新增/替换/删除/移动、训练参数编辑、收藏筛选和移动端点击移动已实现；桌面拖拽专项体验、复杂历史复制工作流和完整并发冲突展示属于延期扩展，不阻塞本 ADR 的核心交付。普通聊天不会直接修改已保存计划。
