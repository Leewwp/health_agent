# 作息有据文档与 RAG 未来方向研究（#107）

Type: research
Status: research-complete（本轮只输出研究与接缝建议，不实现）
GitHub: https://github.com/Leewwp/health_agent/issues/107
日期：2026-08-28

## 0. 结论摘要

1. 当前作息链路的**结构化事实已覆盖咖啡因、睡眠、午睡、晚间训练四类高频问题**（正式库 15 条 topic 事实 + fixture 5 条），全部带来源、来源版本和 ref_id，回答可追溯；本轮"晚上几点后停止锻炼"类问题由"训练时段"事实给出诚实边界（无统一最佳时间），**不新增固定停止锻炼时刻**。
2. 结构化事实与解释性文档的边界清晰：**数值/截止时间类结论走事实表；"为什么/机制/证据强度"类解释走文档证据（未来能力）**。文档证据只补充来源段落和解释，不负责营养计算、风险判定或训练剂量。
3. 若未来接入文档证据，**最小接缝已经存在**：`HealthResourceProvider` 新增文档读取方法、`routine_fact` 同构扩展 `routine_doc` 读取模块、RAG 评估复用 health-eval-v2/分层 RAG 报告框架、Trace 复用现有 `AgentTraceService` 脱敏与事件模型。**不需要新增 schema 之外的基础设施**，也不需要向量库以外的检索组件。
4. 路由原则保持三句话：**结构化事实优先、文档证据补充、无证据不猜测**。命中事实 → 直接返回事实卡；命中主题但无事实 → 返回主题边界说明；连主题都不命中 → 转领域澄清，不跨域返回餐食或动作资源。

## 2. 结构化事实与解释性文档的区分

| 维度 | 结构化事实（现状） | 解释性文档（未来） |
|---|---|---|
| 内容形态 | 一句可独立的结论 + 数值区间 + 适用人群 | 段落/章节，含机制、证据强度、适用条件讨论 |
| 数据库形态 | `routine_fact(topic, fact_zh, scope, source, source_version, ref_id)` | `routine_doc(topic, title, section, content, source, source_version, ref_id)`（同构扩展，不建第二套体系） |
| 回答方式 | 直接返回事实卡（`ROUTINE` 资源，`sourceType=SOURCE`） | 引用段落 + 来源引用，附加在事实卡或边界说明之后 |
| 确定性 | 100% 确定性查询（关键词 → 类别 → topic 过滤） | 检索式（关键词/embedding），需要评估 |
| 风险 | 低（话术固定、来源明确） | 中（可能引入弱证据或断章取义，必须带来源与限定语） |
| 落库门槛 | 来源核验 + 措辞审核 | 来源核验 + 段落切分 + 主题标注 + 审核状态（复用 `review_status` 口径） |

当前已核验事实中**不宜升级为文档检索**的条目：`训练时段`类事实必须保持"无普遍最优"的确定性口径——若引入文档检索，模型可能从单篇研究段落中"归纳"出与事实表冲突的时段建议，这违反 ADR-0016 的无证据不猜测原则。

## 3. 来源、版本、主题、引用与失效策略（未来实现的设计草案）

1. **来源（source）**：沿用 `routine_fact.source` 口径——机构 + 文献标识（作者/年份/期刊），一手链接保存在研究文档而非数据库；数据库只存可展示的来源名。新增条目必须先经 `research/routine-sources.md` 同等级的一手核验。
2. **版本（source_version）**：事实与文档各带 `source_version`（来源年份/版本号）；建议补充**事实集版本号**（如 `ROUTINE_FACTS_VERSION`，类似 `RiskRuleCatalog.PROFILE_RULES_VERSION` 的既有模式），用于 Trace 记录与评估快照对齐。
3. **主题（topic）**：topic 即"路由键"。`RoutineModule.KEYWORD_CATEGORY` 的关键词→主题映射必须与 topic 集合同步版本化（注释里已约定"调整时同步种子版本"）；新增主题时三类落点必须一起变：关键词映射、事实/文档 topic、评估查询集。
4. **引用（citation）**：响应中的事实卡已带 `sourceName`；文档证据若接入，每段证据必须携带 `ref_id` + `source_version` 并在响应中可见，禁止只给结论不给来源。
5. **失效（invalidation）**：
   - 来源被撤回/更正 → 更新或删除对应行并提升事实集版本号，评估报告按版本号区分前后口径；
   - "待复核"条目（健康中国行动链接、中国失眠指南条文）复核不通过 → 删除，不降级为"弱证据"继续使用；
   - 文档证据设 `review_status`（复用现有 APPROVED 语义），未审核文档不进入回答；
   - 路由关键词映射变更必须与事实集版本同步发布，避免"关键词命中但事实已下线"的空回答。

## 4. 最小接缝评估（复用现有架构，不新增基础设施）

| 现有接缝 | 复用方式 | 需要的增量 |
|---|---|---|
| `HealthResourceProvider`（资源唯一入口） | 新增 `routineDocs(topic)` 类方法；DB/fixture 双模式语义照抄 `routineFacts()` | Provider 接口 + 2 个实现；架构测试 `HealthResourceReadBoundaryArchitectureTest` 已约束 Reader 边界，无需改动 |
| `DbReviewedResourceProvider` / `DbReviewedExerciseReader` 模式 | 新建 `routine_doc` 对应的读取 adapter（仅 Provider 可依赖 Mapper） | 一个 Mapper 方法 + XML（LIKE/主题过滤，可先不做向量） |
| `RoutineModule` | lookup 命中事实 → 事实卡；命中主题无事实 → 边界说明；未来在两者之间插入"文档证据补充段" | 一个可选的文档查询步骤，失败静默降级为现状 |
| RAG 评估（health-eval-v2 / 分层 RAG 报告） | 作息问题加入评估查询集：`domain/task` 断言、来源字段非空断言、无事实时的边界说明断言 | 扩充 JSONL 查询集 + 作息专项断言；报告框架零改动 |
| `AgentTraceService` | Trace 记录主题命中、事实/文档来源版本、是否降级 | 事件字段扩展，脱敏规则沿用 |
| Qdrant 向量索引 | 仅当文档证据需要语义召回时使用；事实查询永远不需要向量 | 无（可选） |

**工作量量级**（供排期参考）：仅结构化事实扩充 = 数据条目 + 关键词映射 + 评估用例（天级）；接入文档证据（无向量）= 上述接缝增量（周级）；文档证据 + 语义召回 + 评估闭环 = 完整一轮 RAG 交付（与 77 号分层 RAG 同量级）。

## 5. 路由建议（实现时的行为契约）

1. **结构化事实优先**：`RoutineModule.supportsFactQuery` 命中且有对应 topic 事实 → 直接返回事实卡（现行为，保持）。多个事实命中同一主题时按 Provider 顺序取前 3 条，确定性输出。
2. **文档证据补充（未来）**：事实回答后可附 1–2 段带来源的解释性段落；文档证据缺失或未审核时静默省略，**绝不影响事实卡本身**。
3. **无证据不猜测**：命中主题但无事实 → 固定边界说明（如"训练时段没有统一的最佳时间，应按个人昼夜节律安排"）；连主题都不命中 → 不转入餐食/健身任务，按 `OTHER + CHAT` 领域澄清处理（#106 已实现该门槛）。
4. **禁止事项**：不为"停止锻炼"写固定时刻；不把观察性关联写成因果；不引用未核验的中文来源；不让文档检索结果覆盖事实表结论。

## 6. 本轮边界（不实现清单）

- 不新增 `routine_doc` 表、不接入文档语料、不启用向量检索；
- 不修改 `RoutineModule` 的关键词映射语义（本轮只补了"锻炼"关键词以修复跨域路由，见 #106）；
- 不为"晚上几点后停止锻炼"新增固定答案——继续复用"训练时段无普遍最优"事实与边界说明；
- 不重开已关闭票；后续实现以本文件第 3–5 节为设计输入，另立实现票。
