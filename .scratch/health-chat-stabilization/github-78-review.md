# GitHub #78 对照审查与最终计划

审查对象：GitHub issue #78「P0：面试演示健康聊天主链路稳定化」，当前状态为 `OPEN`，标签为 `ready-for-agent`。

## 计划一：#78 原始计划

目标是让项目具备可复现的面试演示路径，范围包括：

1. 校验仓库根目录 `.env` 加载、环境变量覆盖关系和真实 Agent 模式。
2. 增加启动状态的脱敏可观测信息，区分真实 Agent、fixture 和确定性降级。
3. 修复 Compose `depends_on`，保证 MySQL、Qdrant、应用和 Nginx 的启动配置可解析。
4. 稳定健康聊天的多轮上下文、餐食/健身槽位隔离、`ADJUST` 历史排除和显式领域切换。
5. 复用动作词汇归一，修复餐食审核状态在 SQL `LIMIT` 前过滤的问题。
6. 通过健康聊天 API、真实 DashScope、真实浏览器和部署检查完成面试验收。

这是一个偏完整的“演示环境 + 主流程”稳定化方案，适合以面试演示环境为交付目标。

## 计划二：本轮对话确认的最小修复计划

目标是先满足基本功能：用户提出餐食或健身需求时得到对应领域的结果，缺少信息时只追问相关问题，不能出现跨领域或无关内容。计划拆为四票：

1. 意图与输入归一：增加 `OTHER + CHAT`；增加意图修正；统一模型输出和 fallback 的别名归一、否定处理和低置信度澄清。
2. 多轮编排隔离：按活动领域投影槽位和资源历史；短答只继承当前领域；显式切换覆盖旧领域；`ADJUST` 只排除同域资源；响应块做类型一致性校验。
3. 简单边界修复：作息只做结构化事实查询；审核餐食状态在 SQL `LIMIT` 前过滤；修复 Compose YAML。不得借此扩展作息规划、RAG 或数据集。
4. 回归与验收：覆盖餐食、健身、作息、`OTHER`、跨域切换、别名输入、风险和周计划入口；执行编译、测试、MySQL 门控、Compose 校验以及可用时的真实模型和浏览器冒烟。

最低词汇集合明确支持：

- “胸肌/胸部/胸大肌” → “胸”；
- “背部/背肌” → “背”；
- “大腿/小腿/腿部” → “腿”；
- “肩部” → “肩”；
- “胳膊” → “手臂”；
- “腹部/腹肌/腰腹” → “核心”；
- “臀部/臀肌/臀大肌” → “臀”；
- “新手/初学者/轻量” → “入门”；
- “减肥/瘦身” → “减脂”；
- “自重/无器械/不用器械” → “徒手”。

未知、冲突或否定表达不能安全映射时，系统澄清而不是猜测。

## 冲突与裁决

## 最终合并方案

本轮以四张最小修复票为实施真源：

1. `01` 意图修正与输入归一，先建立 `OTHER`、别名和 fallback 一致性。
2. `02` 多轮编排与跨品类隔离，依赖 `01` 后接入主编排流程。
3. `03` 作息事实、审核餐食查询和 Compose 边界修复，依赖前两票但不扩展领域能力。
4. `04` 回归与基本功能验收，覆盖所有用户可观察的冲突场景。

保留 #78 中与本轮不冲突的约束：使用现有健康编排状态机、Provider/Reader 资源边界、类型化资源、候选 ID 白名单、匿名会话、无 schema migration、不做软约束放宽、不引入 React 和复杂 NLP。`.env`、真实 Agent、Compose、MySQL、真实浏览器属于验收前置或边界检查；只有当检查发现直接阻塞基本聊天功能时才修复，不把面试环境增强重新扩成独立的核心工作流。

最终验收必须证明：餐食只返回餐食，健身只返回动作，作息只返回作息事实，`OTHER` 不返回健康资源；“胸肌”“大腿”“臀部”等回答可完成健身推荐；跨领域切换不带入旧槽位；不确定输入进入澄清；周计划继续走已有入口。
