# 02 — 餐食推荐、调整和跨品类切换闭环

**Parent:** GitHub #78

**GitHub:** [#80](https://github.com/Leewwp/health_agent/issues/80)

**What to build:** 用户可以完成“中午吃什么”“早餐清淡点”“换一批”等基本餐食交互；从健身切换到餐食，或从餐食切换到健身时，系统不携带旧领域槽位、资源或澄清问题。餐食结果必须继续来自审核公共资源。

**Blocked by:** #79 / 01 — 健身最小推荐闭环与意图安全基础。

**Status:** resolved

- [x] `MEAL + RECOMMEND` 请求只使用餐食槽位；“早餐/午餐/晚餐/清淡”等已有语义可完成餐食澄清和推荐。
- [x] 餐食短答只继承当前餐食上下文；`ADJUST` 只排除上一轮同领域餐食资源。
- [x] 餐食响应只返回 `MEAL` 展示块；领域切换后不携带旧健身槽位、动作历史或健身澄清问题。
- [x] 审核状态、公共来源和 owner 条件在 SQL `LIMIT` 前过滤；未审核行不能消耗结果窗口，审核早餐资源仍可正常返回。
- [x] 不放宽餐食硬约束、不扩展数据集、不绕过现有审核 Provider/Reader；补充 API 和真实 MySQL 门控回归。

## Answer

编排层按活动领域投影槽位与资源历史，`ADJUST` 只排除同域资源；餐食 Mapper 在 `LIMIT` 前执行审核/公共/owner 过滤，真实 MySQL 回归已覆盖。
