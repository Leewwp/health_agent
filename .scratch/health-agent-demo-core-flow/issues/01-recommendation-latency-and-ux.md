# 01 — 推荐主流程延迟与交互闭环

Status: ready-for-agent

GitHub: [#84](https://github.com/Leewwp/health_agent/issues/84)

**What to build:** 让明确的餐食和动作推荐从聊天输入到结构化卡片完整跑通，避免不必要的模型等待，并在慢请求、超时和降级时提供正常的用户反馈与可诊断事件。

**Blocked by:** None — can start immediately.

- [ ] 明确餐食、动作和计划短语走确定性意图快路径，歧义或复合表达最多调用一次结构化理解 Agent。
- [ ] Clarify 改为确定性缺失字段模板，不再产生文本 Prompt 与 JSON 解析冲突，也不调用模型。
- [ ] 先记录明确请求、歧义请求和当前串行 Agent 的客户端/Trace 基线；发布门槛固定为云端 Chromium 热请求等待反馈 ≤100ms、明确餐食/动作推荐 P95 ≤3 秒且单次 ≤5 秒、歧义 Agent 请求单次 ≤15 秒，冷启动单独记录。
- [ ] 整轮请求、模型调用、Nginx 和前端等待时间使用同一截止时间语义并满足“模型 < 应用 < Nginx < 前端”；持久化前重检应用截止时间，超时后不继续不可见写入。
- [ ] 餐食和动作请求展示可见等待动画、阶段文案、防重复提交、超时/失败恢复和正常中文 fallback；无 SSE/轮询时不得把阶段文案冒充精确服务端实时进度。
- [ ] 餐食卡直接携带已有营养与来源字段，餐食/动作卡主体可打开详情抽屉，收藏和反馈不误触抽屉。
- [ ] Trace 能区分快路径、真实 Agent 和 fallback，并记录实际模型、耗时、解析状态和稳定降级原因。
- [ ] 快路径、歧义回退、超时和重复提交具有控制器/编排器级回归测试。
- [ ] 在运行中的同源应用用真实 Chromium 验证餐食、动作、加载、详情和失败恢复，记录 URL、交互和结果。
