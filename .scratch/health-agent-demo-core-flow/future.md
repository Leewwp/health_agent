# 健康 Agent 面试演示核心流程 — 未来任务归档

Status: future

Tracked from: [GitHub #83](https://github.com/Leewwp/health_agent/issues/83)

本文件保存原规格中已经明确延期的工作。它们没有被否定，但不属于当前六票合计 9–14.5 人日的面试演示 MVP，也不应被当前 `ready-for-agent` 票据顺带实现。

## 重新启动原则

只有同时满足以下条件时，才把某项未来任务重新拆票：

1. 四项核心能力已经在云端重复跑通：餐食推荐、动作推荐、Agent 训练计划、Trace。
2. 普通请求延迟、加载反馈、失败恢复和页面布局已经达到演示要求。
3. 新任务能增加可证明的用户价值或面试叙事，而不只是增加技术名词。
4. 有独立测试接缝、验收脚本和预计投入，不侵入当前稳定主流程。

## F1 — 对话式计划调整

- MOVE、REPLACE、ADD、REMOVE。
- 整日移动、整周重生成和任意自然语言编辑。
- ACTIVE 计划复制为新草稿后的复杂调整流程。
- Undo/redo 和调整历史页面。

重新启动条件：Agent 生成草稿和版本激活稳定后，确实需要第二条面试演示链路。

## F2 — 个性化作息与指南证据

- 作息多轮收集和确认。
- Agent 生成个性化睡眠/作息计划。
- 训练和作息指南证据检索、引用片段和向量化。
- 作息与训练时段的高级联合优化。

重新启动条件：有可靠、版本化、可引用的指南数据，并能定义比确定性规则更有价值的 Agent 决策。

## F3 — 完整综合周计划个性化

- 将餐食偏好完整映射到七日餐食计划。
- Agent 联合决定餐食、训练和作息项目。
- 多份计划需求简报、跨会话复用、历史、回滚和管理页面。
- 多个并行草稿和复杂重新生成。

重新启动条件：训练计划闭环完成，并且餐食计划联动有明确演示价值和可控数据合同。

## F4 — 高级训练处方与数据扩展

- Agent 生成组数、次数、重量、强度和恢复周期。
- 全量 1,324 动作的计划资格审核。
- 复杂训练目标体系、周期化计划和动作知识图谱。
- 训练效果预测、康复或竞技训练。

重新启动条件：获得专业规则、可靠数据和新的安全评审；不得仅通过 Prompt 扩展。

## F5 — 完整 Trace 工作台

- Trace 列表/详情 API 拆分和懒加载。
- 原始 JSON 下载、复杂标注工作台和批量诊断。
- 20,000 字符 payload 压力场景和六个视口宽度的穷举回归。
- 高级关键路径聚合、跨请求对比和统计面板。

重新启动条件：最小 Trace 已无法定位真实问题，或大响应体经测量成为性能瓶颈。

## F6 — RAG 与向量基础设施扩展

- Qdrant 成为强制云端依赖。
- 向量库重设计、embedding 迁移和大规模索引调优。
- 训练/作息 RAG、多阶段 rerank 和大规模离线评估。
- 为展示技术而增加没有可复现收益的检索链路。

重新启动条件：有新的查询集和可复现收益；若收益仍微小，继续保持 Qdrant 可选。

## F7 — 生产化与平台扩展

- SSE/WebSocket/token 流式输出和后台任务系统。
- Redis、消息队列、多实例、分布式锁、自动扩缩容和 Kubernetes。
- 正式账号、角色、租户、医疗合规平台、审核后台和长期数据清理。
- 前端框架迁移、Node/npm 构建链、全站视觉重设计和原生移动端。

重新启动条件：真实负载或产品需求证明单实例演示拓扑不足。
