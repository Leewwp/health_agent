# 健康 Agent 统一综合周计划与时间网格编辑器规格

Status: ready-for-agent
Type: spec
Date: 2026-08-20

## Problem Statement

当前健康 Agent 已经具备动作推荐、餐食推荐、训练计划和餐食计划的部分后端能力，但用户侧计划流程仍按餐食/训练范围拆分，计划启用行为会让同品类旧计划进入历史，无法保存多份可切换的计划模板。聊天中的餐食计划请求还可能落入旧的“进入我的计划、不会在聊天里创建计划”兜底文案，无法完成从简报确认到周餐食计划生成的闭环。

“我的计划”页面也没有形成完整的用户编辑闭环：收藏无法作为新增或替换候选筛选，计划项目不能新增、删除或替换资源，训练时间和训练细节调整能力不足，现有操作名称无法让用户理解计划是否已经正式保存或正在执行。桌面和移动端都缺少适合周计划的时间安排视图。

本规格面向面试演示的最小可用闭环，重点是让推荐、三种周计划生成、计划切换和计划内容调整都能在本地稳定跑通。

## Solution

将用户可见的计划统一为一份可同时容纳餐食和训练项目的综合周计划。用户只请求餐食或训练时，仍生成综合周计划，但计划中只包含对应类型的项目；用户明确请求两者时，生成同时包含完整餐食和训练内容的综合周计划。

计划生命周期改为“草稿、未启用、已启用、历史”。用户可以保留多份未启用计划，并在需要时启用其中一份；启用新计划只会让旧计划回到未启用，不会自动归档。已启用计划必须先停用才能转为历史。计划编辑通过草稿或编辑副本完成，不直接破坏当前已启用计划。

“我的计划”详情以时间网格为中心，提供“全部、餐食、动作”切换。时间按半小时分格；用户可以点击空白格新增项目、打开项目进行替换或调整、删除项目，也可以在桌面拖拽项目移动，在移动端通过选择项目后点击目标格移动。项目时间不得重叠。新增和替换候选使用审核资源库，并支持“仅看收藏”。

聊天必须完成以下面试演示流程：动作推荐、餐食推荐、周餐食计划、周训练计划和完整周计划。完整周计划分别收集并确认餐食简报和训练简报，再一次性生成包含两类项目的草稿。计划编辑暂不通过普通聊天直接改写已保存计划，但保留后续由 Agent 读取当前启用计划并生成增量编辑副本的扩展边界。

## User Stories

1. As a 健康 Agent 用户, I want to获得动作推荐, so that我能浏览和选择审核动作资源。
2. As a 健康 Agent 用户, I want to获得餐食推荐, so that我能浏览和选择审核餐食资源。
3. As a 健康 Agent 用户, I want to说“给我生成本周饮食计划”, so that我能进入餐食计划简报而不是被引导到一个不会生成计划的旧入口。
4. As a 健康 Agent 用户, I want to补充“每天三餐”, so that系统能完成餐次确认并继续生成周餐食计划。
5. As a 健康 Agent 用户, I want to在简报确认后直接触发餐食计划生成, so that我不需要重复寻找另一个隐藏入口。
6. As a 健康 Agent 用户, I want to生成一份只有餐食项目的综合周计划, so that我可以先管理饮食而不被迫提供训练需求。
7. As a 健康 Agent 用户, I want to完成周训练简报, so that系统能生成一份只有动作项目的综合周计划。
8. As a 健康 Agent 用户, I want to完成周完整计划, so that同一份计划中同时包含完整餐食和训练内容。
9. As a 健康 Agent 用户, I want to看到综合计划生成中的等待状态和失败提示, so that我能区分生成中、生成成功和需要调整条件的情况。
10. As a 健康 Agent 用户, I want to保存多份日常、减脂和增肌计划, so that我可以按当前目标切换模板。
11. As a 健康 Agent 用户, I want to看到计划名称、目标周和状态, so that我能区分多份内容相似的计划。
12. As a 健康 Agent 用户, I want to把未确认结果标记为草稿, so that我知道它仍可直接编辑或删除。
13. As a 健康 Agent 用户, I want to确认草稿成为未启用计划, so that我可以保留它并稍后决定是否使用。
14. As a 健康 Agent 用户, I want to同时保存多份未启用计划, so that启用一份不会破坏其他候选计划。
15. As a 健康 Agent 用户, I want to启用一份未启用计划, so that它成为聊天和近期执行的参考计划。
16. As a 健康 Agent 用户, I want to启用另一份计划, so that旧的已启用计划回到未启用而不是变成历史。
17. As a 健康 Agent 用户, I want to停用当前计划, so that我可以暂时停止使用它而不删除记录。
18. As a 健康 Agent 用户, I want to删除未启用计划, so that它转为历史并不再出现在可启用候选中。
19. As a 健康 Agent 用户, I want to先停用已启用计划再删除, so that正在使用的计划不会被误删。
20. As a 健康 Agent 用户, I want to查看历史计划, so that我能回顾过去的安排和演示过程。
21. As a 健康 Agent 用户, I want to在计划详情中切换“全部、餐食、动作”, so that我能快速聚焦某一类项目。
22. As a 健康 Agent 用户, I want to在周表中看到早餐、午餐和晚餐的对应时间, so that生成的完整餐食项具有可执行位置。
23. As a 健康 Agent 用户, I want to在一天安排多个项目, so that我能同时安排多餐和多次训练。
24. As a 健康 Agent 用户, I want to项目不能时间重叠, so that周计划不会安排无法同时执行的活动。
25. As a 健康 Agent 用户, I want to按半小时网格查看计划, so that我能理解每个项目的开始和结束时间。
26. As a 健康 Agent 用户, I want to点击空白时间格, so that我能在指定日期和时间新增餐食或动作。
27. As a 健康 Agent 用户, I want to从审核资源中搜索新增候选, so that计划不会引用系统之外的虚构内容。
28. As a 健康 Agent 用户, I want to只看收藏资源, so that我能快速把喜欢的餐食或动作加入计划。
29. As a 健康 Agent 用户, I want to替换计划中的餐食, so that我能保留时间位置但改变具体资源。
30. As a 健康 Agent 用户, I want to替换计划中的动作, so that我能根据喜好改变训练资源。
31. As a 健康 Agent 用户, I want to删除某个餐食或动作, so that我能清理不想执行的项目。
32. As a 健康 Agent 用户, I want to调整训练日期和时间, so that周计划符合我的实际安排。
33. As a 健康 Agent 用户, I want to调整训练时长、组数和次数, so that我能对确定性计划参数做小幅修改。
34. As a 健康 Agent 用户, I want to在桌面端拖拽训练项目, so that我能快速把早上的训练移动到下午。
35. As a 健康 Agent 用户, I want to在移动端通过选择项目和目标时间格移动, so that触控操作不会被长按拖拽和页面滚动冲突阻塞。
36. As a 健康 Agent 用户, I want to一次保存多项计划调整, so that拖拽和新增过程不会产生难以理解的中间状态。
37. As a 健康 Agent 用户, I want to取消未保存的编辑, so that误操作不会影响计划草稿或已启用计划。
38. As a 健康 Agent 用户, I want to编辑已启用计划时自动得到副本, so that当前正在使用的安排保持稳定。
39. As a 健康 Agent 用户, I want to保存调整后的计划但不自动启用, so that我可以检查完整结果后再切换。
40. As a 健康 Agent 用户, I want to在餐食与训练时间冲突时得到明确提示, so that系统不会静默覆盖我的安排。
41. As a 健康 Agent 用户, I want to在训练窗口没有可用时段时看到失败原因, so that我知道需要调整训练时间而不是误以为计划已生成。
42. As a 健康 Agent 用户, I want to在健康档案不完整或风险规则阻断时得到明确入口, so that计划不会绕过必要的安全校验。
43. As a 面试演示者, I want to从新会话完成动作推荐、餐食推荐和三种计划生成, so that核心 Agent 能力可以连续展示。
44. As a 面试演示者, I want to展示计划启用、停用、删除和切换, so that计划生命周期的产品逻辑清晰可见。
45. As a 面试演示者, I want to展示替换、添加、删除和拖拽, so that计划不是一次性只读生成结果。
46. As a 面试演示者, I want to在桌面和移动视口完成计划编辑, so that演示不会依赖单一屏幕尺寸。

## Implementation Decisions

- 沿用现有健康聊天状态机和计划服务边界。推荐、简报确认、生成和持久化仍由健康编排层协调，资源候选继续经过审核资源 Provider/Reader，计划写入继续经过风险 Guard 和确定性计划校验。
- 所有新计划统一保存为可容纳餐食和动作项目的综合周计划。餐食-only 和训练-only 计划的另一类项目为空，不再向用户暴露餐食计划、训练计划和综合计划三种互斥类型。
- 计划需要用户可见名称。生成时提供稳定默认名称，并允许在计划详情中修改，以区分日常、减脂、增肌等并存计划。
- 计划状态采用四态：`DRAFT` 表示未确认草稿；`UNENABLED` 表示已确认但未使用的计划模板；`ENABLED` 表示当前正在使用的计划；`HISTORY` 表示主动删除或保留的历史记录。若实现继续兼容现有数据库状态值，API 和前端必须对用户呈现上述语义，不能继续显示“激活”或“当前安排”。
- 每个用户同一时间最多一份已启用计划。启用另一份计划只替换当前引用，原已启用计划回到未启用；启用操作不得自动归档旧计划。
- 未启用计划可以转为历史；已启用计划必须先停用再转为历史；草稿可以在确认前直接删除。历史计划默认可查看但不可直接编辑或启用，除非先复制为新草稿。
- 已启用计划不可原地修改。编辑已启用计划先创建副本；草稿和未启用计划可以进入编辑态。保存调整后计划仍为未启用，必须显式启用才替换当前计划。
- 计划详情使用“全部、餐食、动作”分段切换，不再通过计划类型切换。每个项目保留类型化资源身份、日期、开始时间、结束时间和计划参数。
- 时间编辑器以每半小时为一个网格单元。桌面端支持项目拖拽并吸附到最近半小时；移动端使用选择项目后点击目标时间格移动，避免触控拖拽与滚动冲突。
- 一天允许多个餐食或训练项目，但任何两个项目不得时间重叠。空白格点击可以新增餐食或动作；新增、替换、删除和移动都必须在服务端重新执行日期范围、时间粒度、重叠、资源存在性、计划资格和风险校验。
- 新增/替换资源的候选来自审核餐食和动作资源库，支持现有搜索、结构化筛选和“仅看收藏”。收藏只影响候选过滤，不自动改变 Agent 排序，也不等同于加入计划。
- 餐食生成按确定性窗口放置项目：早餐 `08:00-08:30`、午餐 `12:00-13:00`、晚餐 `18:00-19:00`。用户编辑时可以移动餐食，但餐次标签保留；超出常用餐次窗口时显示警告，不静默拒绝。
- 综合计划生成先放置完整餐食项目，再在用户确认的训练日期和时间窗口内寻找不与餐食重叠的训练时段。没有满足训练时长的可用时段时返回明确生成失败，不自动改变用户时间约束。
- 训练项目替换后，资源相关的组数、次数和时长使用确定性规则重新计算；用户可以在编辑态调整时长、组数和次数。参数必须是合法正值，并继续经过计划校验。
- 计划编辑采用显式保存：用户可以在页面内累积多项修改，看到未保存状态，选择保存或取消。保存失败需要回滚编辑状态并展示稳定错误。
- 后续可扩展“基于当前启用计划增加训练动作”等 Agent 增量计划调整，但本规格只要求用户在“我的计划”页面完成编辑，不要求普通聊天直接修改已保存计划。
- 页面移除计划页右上角重复的健康档案按钮；缺少档案时只在生成失败或缺档案流程中提供完善档案入口。
- 计划页弱化顶部统计卡，把餐食餐次、热量、动作部位、时长、组数和次数放回周表项目；状态和主要操作集中在计划标题区域。

## Testing Decisions

- 测试优先验证外部行为和状态转换，不断言私有 helper、具体 Agent 文案或数据库实现细节。相同契约必须同时覆盖确定性 fallback 和可用的真实 Agent 路径。
- 以健康聊天 API/健康编排器作为最高层生成 seam，覆盖动作推荐、餐食推荐、餐食简报、训练简报、综合双简报和生成请求幂等。
- 以计划 API/计划服务作为生命周期 seam，覆盖草稿确认、多个未启用计划并存、启用切换、停用、未启用转历史、已启用删除拒绝、历史只读和编辑副本。
- 以计划项目 API/计划校验作为编辑 seam，覆盖新增、替换、删除、日期移动、半小时粒度、训练参数修改、时间重叠拒绝、跨周拒绝、资源不存在、非计划资格动作和空计划启用拒绝。
- 以当前启用计划上下文作为聊天消费 seam，覆盖餐食问题只读取当前计划餐食项目、训练问题只读取动作项目、明确当前请求优先、停用后不再读取计划项目。
- 以资源浏览/读取接口作为候选 seam，覆盖搜索、类型筛选、仅看收藏、资源详情和候选不绕过审核边界。
- 前端行为测试覆盖状态标签、计划操作按钮的互斥可见性、详情 Tab、空白格新增、替换/删除侧栏、未保存修改、桌面拖拽吸附、移动端点击移动和失败回滚。
- 真实浏览器验收覆盖桌面和移动端：从聊天完成三种周计划生成，在计划页切换餐食/动作，启用两份计划互换，停用后删除，新增/替换/删除项目，桌面拖拽训练，移动端点击移动，确认无横向溢出和无时间重叠。
- MySQL 门控测试覆盖计划状态迁移、当前启用唯一引用、历史转换、项目增删改事务和并发冲突；不要求 Qdrant 或 live model 成为本地核心闭环的必要条件。
- 浏览器证据记录 URL、视口、输入、操作、结果、等待/错误状态和截图路径，不记录真实密钥、完整 prompt 或敏感用户数据。

## Out of Scope

- 不实现普通聊天对已保存计划的即时修改；Agent 增量修改当前计划属于后续规格。
- 不实现同一时间段项目重叠、并行训练或并行餐食。
- 不实现任意拖拽排序、跨周拖拽、月历视图、日历同步、提醒、打卡或执行追踪。
- 不实现一天多个训练窗口之外的复杂强度周期、竞技训练处方或医疗康复方案。
- 不允许 Agent 自由创造餐食、动作、训练剂量、风险规则或烹饪方法；候选和剂量仍受审核资源与确定性规则约束。
- 不实现收藏分类、批量收藏管理、收藏自动提升排序或类别级偏好推断。
- 不实现完整生产级多用户账号、权限后台、计划协作和跨设备实时同步。
- 不以全量动作目录资格扩容、Qdrant 可用或真实模型可用作为本地核心演示通过的前提。

## Further Notes

- 本规格与旧的按 `MEAL`/`EXERCISE` 分离当前安排、启用新计划即归档旧计划的计划假设不同；统一模型的架构理由记录在 ADR-0014，后续实现应以本规格和 ADR-0014 为准。
- 计划编辑器是面试演示中最容易被误操作暴露的区域。实现时应优先保证状态可见、保存边界明确、冲突错误可解释，而不是优先增加复杂拖拽效果。
- 第一阶段应先完成统一计划状态和三种生成垂直闭环；第二阶段再实现时间网格编辑器，两个阶段都通过后才采集最终面试演示证据。
