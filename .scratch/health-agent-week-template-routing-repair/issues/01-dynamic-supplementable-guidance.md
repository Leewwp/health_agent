# 01: 动态需求输入指引

**What to build:** 餐食、训练和综合简报的“还可以补充”与引导文案不再使用固定文本，而是由当前结构化简报统一动态计算：已填写的受支持字段不再重复提示，全部可选项填满后不再显示“还可以补充”，未支持值（如菜系“中餐”）单独说明“已记录，暂不按它筛选”并继续提示受支持选项；未完整、解析失败和完整三个分支共用同一动态列表；响应中的可补充项结构是前端渲染的唯一来源，旧响应缺少该字段时不恢复全量固定提示。

**Blocked by:** None (can start immediately)

**Status:** resolved（2026-08-30 实施完成，双门控 907/0 全绿 + 真实浏览器验收）

- [ ] 已填写受支持的菜系/餐食类型/口味/烹饪时长后，指引不再列出对应可补充项（US 10/11）
- [ ] 全部可选项填满后不再出现“还可以补充”（US 12）
- [ ] 未支持菜系“中餐”保留在简报未支持集合，同一响应同时给出“已记录，暂不按它筛选”和受支持菜系提示（US 13/14）
- [ ] 未完整、INVALID/解析失败和完整三个分支返回同一动态可补充项计算，无独立固定枚举全文兜底（US 15）
- [ ] 动态列表不含目标周/周一日期类条目；前端只消费响应的可补充项结构，旧响应缺字段时明确兼容显示而非恢复固定提示（US 10-15）
- [ ] 训练简报未填的训练部位/器材/目标/难度等被动态列出，已填项消失
- [ ] 服务层与端到端回归通过；确定性/fixture 模式与正式模式对同一输入产生同等指引结构
- [ ] 真实浏览器验收：已填菜系后指引变化、未支持“中餐”提示可见、可选填满后无“还可以补充”，记录 URL、交互和结果

**规范来源:** spec.md「需求输入指引动态化」与 Testing Decisions「动态指引测试」。
