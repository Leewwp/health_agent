# 04: 训练优先餐训时间适配

**What to build:** 综合计划生成中，餐食时间由确定性、可单测的适配器在训练硬约束之后安排：先尝试餐次默认窗口（早餐 08:00、午餐 12:00、晚餐 18:00，时长早 30/午 60/晚 60 分钟），冲突时先试训练结束后立即开始用餐（无额外间隔、相邻区间合法），再试训练开始前倒推相同时长；同日多次训练按时间顺序逐一避让；可行边界为本地 05:00–24:00，餐食不得跨午夜；前后均无可行时段时整体失败并回滚。自动适配成功不视为冲突、不触发误导性窗口告警；被移动的餐次和方向对用户可见，并记录在生成说明/metadata/版本快照/Trace。最终 Guard（重叠、粒度、跨午夜、周范围、资源资格、风险）保留。

**Blocked by:** None (can start immediately; 聊天修改触发路径的端到端验收与票据 02 联调)

**Status:** resolved（2026-08-30 实施完成，双门控 907/0 全绿 + 真实浏览器验收）

- [ ] 晚餐 18:00-19:00 与训练 18:00-19:00 冲突时自动移入训练结束后 19:00-20:00；餐食开始时间等于训练结束时间合法（US 16/17/19）
- [ ] 训练后无法放置时倒推到训练开始前相同时长；前后均无可行时段返回稳定错误，综合计划整体失败并回滚，不留下半成品计划（US 21）
- [ ] 同日多次训练按训练起始时间稳定排序逐一避让，重复生成结果可复现（US 20）
- [ ] 餐食可离开默认窗口但不得跨午夜；05:00/24:00 边界判定正确；相邻区间按 `[startTime,endTime)` 视为合法（US 18）
- [ ] 自动适配不产生 `SCHEDULE_OVERLAP`，成功适配结果不触发误导性的餐次窗口/重叠告警；窗口外状态以“系统适配结果”表达而非风险或失败（US 23）
- [ ] 被移动的餐次、方向（训练前/训练后）、原始与最终窗口记录在生成说明、metadata、版本快照与 Trace；用户在聊天回复或计划页生成说明至少一处可见（US 22）
- [ ] 训练项目保持用户输入的时间不受影响；餐食-only 和训练-only 生成不意外启用综合适配
- [ ] 既有 Guard 回归：真实重叠、资源资格、风险、半小时粒度、零时长、跨午夜、跨周仍按原规则阻断；适配器无解后的真实餐训重叠仍阻断
- [ ] 单元/MySQL 集成/端到端覆盖：失败事务不留下项目或版本；幂等快照与版本说明含适配记录
- [ ] 真实浏览器验收：综合计划自动适配结果可见、移动端无横向溢出，记录 URL、交互和结果
