# 05: 歧义任务单次受约束仲裁

**What to build:** 当确定性规则无法唯一裁决（多个任务候选、规则与会话状态冲突、无法区分新建/修改/推荐/作息、否定/转折/指代/多时间从句）时，调用一次轻量意图仲裁，Agent 只返回受限候选任务（如新建计划、修改计划、推荐、作息、闲聊）、领域、置信度和证据；结果经领域/任务枚举、置信度阈值、当前会话计划生命周期、风险规则与资源约束复核，确定性的计划上下文和风险阻断不可被覆盖；超时、非法 JSON、低置信或与会话冲突时澄清并保留规则已抽取的合法槽位，不猜测执行、不回退普通推荐；无歧义输入不调用模型；Trace 记录规则证据、是否仲裁、仲裁摘要、最终裁决与降级原因。

**Blocked by:** 票据 02（共享路由结构化判定先稳定，仲裁作为同接缝的第二层接入）

**Status:** resolved（2026-08-30 实施完成，双门控 907/0 全绿 + 真实浏览器验收）

- [ ] 明确快捷问题与同义表达不调用仲裁，直接确定性路由（US 31/32）
- [ ] 多任务候选/否定/转折/指代/多时间从句输入最多一次仲裁，无重复或递归模型调用（US 33）
- [ ] Agent 输出经受限候选枚举与置信度校验；计划上下文、风险规则和资源约束不被 Agent 决定或覆盖（US 33）
- [ ] Agent 超时、非法 JSON、低置信或与会话状态冲突时进入可理解澄清，保留规则已抽取的合法槽位，不猜测执行、不随意回退普通推荐（US 34/35）
- [ ] 槽位选项准备、快路径与仲裁路径之间无重复模型调用；无歧义路径保持纯规则快路径（US 32）
- [ ] Trace 区分规则证据、Agent 是否调用、仲裁输出摘要、最终裁决与降级原因（US 37）
- [ ] 确定性/fixture 模式与正式模式对同一歧义输入行为一致；仲裁结果复核复用同一会话状态与风险判定
- [ ] 回归（Maven/MySQL 门控/前端）通过，不受新合同影响的既有断言保持原样
- [ ] 真实浏览器验收：歧义输入触发一次可理解澄清，无歧义快捷问题无额外延迟，记录 URL、交互和结果
