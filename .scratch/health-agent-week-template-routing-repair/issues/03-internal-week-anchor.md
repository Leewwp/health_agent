# 03: 统一内部周锚点与目标周移除

**What to build:** `weekStart` 不再作为简报用户必填条件：完整性、缺失项、提问、摘要与需求指引不再要求或展示“目标周”；三个生成入口（餐食、训练、综合）与聊天触发路径在生成边界用同一派生函数计算“生成当天所在周的周一”作为内部锚点；旧会话缺失锚点时按同一规则补齐，已有锚点保持不变，幂等重放复用原计划日期；对话隐藏内部日期，计划页与 API 继续展示具体日期；前端不自行计算周。

**Blocked by:** None (can start immediately)

**Status:** resolved（2026-08-30 实施完成，双门控 907/0 全绿 + 真实浏览器验收）

- [ ] 训练/餐食简报缺少周锚点仍可被判定完整并直接生成；缺失项、提问、摘要和动态指引不含目标周或周一日期（US 1/9）
- [ ] 三个生成入口在同一应用日期生成同一周一，无各模块“本周/下周”各自解析（US 5/38）
- [ ] 旧会话 JSON 缺失锚点时按统一规则补齐；已有锚点保持原值，不因当前日期或用户消息日期改写；requestId 幂等重放复用既有计划日期（US 9）
- [ ] 输入“改成 2026-09-07”“下周安排”不改变简报字段或计划语义，得到简短说明“计划按周一至周日作为参考，不需要指定日期”（US 7/8）
- [ ] 聊天摘要和回复不展示内部日期；计划页仍显示周一至周日及每天具体安排（US 2/3）
- [ ] 计划不因现实日期经过而自动过期，生命周期仍由草稿/未启用/启用/历史操作决定（US 6）
- [ ] 缺省日期注释与实现与派生规则一致，不再残留“缺省为下周一”类过期说明
- [ ] Controller/真实 MySQL：生成接口缺锚点成功并派生一致日期；幂等重放同日期；旧计划、版本与历史 API 保持可读写（US 40）
- [ ] 前端不自行派生周日期（无 nextMonday/本周/下周 类计算），聊天与计划页一律以服务端响应和计划 API 返回的日期渲染
- [ ] 真实浏览器验收：无需目标周直接生成、对话无日期展示、计划页网格日期正常、修改训练时间后重新生成成功，记录 URL、交互和结果

**规范来源:** spec.md「周模板与目标周」与 Testing Decisions「统一周锚点测试」；ADR-0018「周模板与目标周」。
