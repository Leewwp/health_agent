# 02: 计划上下文优先路由（问题 4）

**What to build:** 共享路由判定先识别当前会话是否存在活动计划简报与可解析的字段修改，再决定“活动词 + 时间词”是否作为作息切换；在活动的餐食/训练/综合简报上下文中，“训练时间/训练时段 + 修改表达（改为、调整为、改成、安排到等）”更新对应简报字段并重新展示开始生成入口，不再被路由成 `ROUTINE`；真正的作息事实/建议问句仍进入 `ROUTINE + RECOMMEND`；裸“餐食计划”在已有计划上下文时澄清新建/修改；路由器统一构造方式，生产与测试实例行为一致。

**Blocked by:** None (can start immediately)

**Status:** resolved（2026-08-30 实施完成，双门控 907/0 全绿 + 真实浏览器验收）

- [ ] 完整综合计划后输入“训练时间改为下午五到六点”，返回 `COMPOSITE + PLAN`、训练侧激活、训练时间字段更新、餐食简报不变、开始生成入口重新出现（US 24/25/26）
- [ ] “训练：调整为 17:00-18:00”“把训练安排到晚上七点”回归通过（最小复现必须使用用户原始短句，而非带完整计划摘要的长文本）
- [ ] 真作息问句（无上下文“什么时候训练合适”“训练时段建议”；有计划上下文“晚上几点后停止锻炼”“几点睡”）仍返回 `ROUTINE + RECOMMEND` 且只展示作息事实（US 28/29）
- [ ] 已生成或暂停的简报收到明确修改表达时重新打开对应侧；普通字段短句在已生成/暂停状态不被无条件捕获（US 27）
- [ ] 已有餐食计划上下文时裸“餐食计划”澄清“修改当前餐食计划还是新建一份”，不由模型猜测（US 30）
- [ ] 无活动简报时孤立修改表达（如“把训练安排到晚上七点”）按明确任务词进入对应域的 `PLAN` 创建侧；存在已保存计划但无活动简报时进入“修改当前计划还是新建简报”澄清
- [ ] 共享路由判定（路由判定器、意图修订服务、编排器）对同一输入产生一致结论；判定基于结构化证据而不是新增关键词例外清单
- [ ] 既有路由/意图断言与 health-eval-v2 快照中与新合同冲突的条目更新并注明理由；其余回归保持原样
- [ ] Trace 记录计划字段修改证据、最终裁决与原因，可诊断“ROUTINE 被拒绝/计划字段被捕获”的原因
- [ ] 真实浏览器验收：完整综合计划→修改训练时间→生成入口重现→重新生成成功；真作息问句仍只显示作息事实，记录 URL、交互和结果
