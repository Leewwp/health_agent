# 21 部署资源预算与交付流水线

- Type: grilling
- Status: resolved
- Blocked by: 11, 12

## Question

在腾讯云 4C4G 服务器还要承载另一个更大项目的前提下，健康 agent 的前端、后端、MySQL、Redis 和反向代理如何分配或外置，部署流水线如何保证可回滚与不泄露密钥？

待决策：

1. 前端和后端是否分平台，MySQL/Redis 是共享实例、独立容器还是托管服务。
2. JVM、MySQL、Redis 的资源上限与健康检查；两个项目之间的网络和数据隔离。
3. GitHub Actions 只做编译测试和镜像构建，还是自动 SSH/镜像拉取部署。
4. Flyway 执行时机、备份、失败回滚和旧版本兼容窗口。
5. DashScope key、数据库凭证、session secret 的环境变量和轮换方式。

产出：部署拓扑、资源预算、CI/CD 阶段、回滚清单和运行手册边界。

## Answer

2026-08-10 已决策：

- 静态前端独立托管；后端保持单实例 Spring Boot，MySQL、Redis 和反向代理使用隔离容器或同区域托管服务。
- 不部署第二个后端实例，不引入 Redis 分布式锁和消息队列；会话串行与幂等继续使用单实例本地方案。
- GitHub Actions 负责编译、核心测试和镜像构建；生产部署采用明确的版本发布和可回滚流程，不把每次普通提交直接发布到生产。
- Flyway 在应用发布阶段执行，发布前备份数据库；迁移保持旧版本兼容窗口，失败时回退应用镜像并按迁移回滚方案处理。
- DashScope key、数据库凭证、匿名身份密钥和其他 session secret 只通过部署环境注入，不进入仓库、镜像或前端；密钥需要支持轮换。
- 公开部署前必须完成健康检查、资源上限、两个项目之间的数据/网络隔离和恢复演练；Vercel 前端还需实际验收中国大陆访问质量。
