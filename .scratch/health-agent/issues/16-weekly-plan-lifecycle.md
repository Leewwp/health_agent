# 16 每周个人计划模型与生命周期

- Type: grilling
- Status: resolved
- Blocked by: 08, 09, 13, 14

## Question

每周个人计划如何建模、校验、持久化和局部调整，使它不是一段无法维护的 LLM JSON？

已确认交互下限：支持生成草稿、确认、启用计划、停用和历史版本，以及在可编辑计划中批量新增、替换、删除、移动项目、保存备注和确定性训练处方；第一版不做任意表格编辑或桌面拖拽。

待决策：

1. 计划聚合根、每日安排、餐食项、训练项、作息项和生成依据快照的关系。
2. `DRAFT / UNENABLED / ENABLED / HISTORY` 状态、版本号、有效周、时区，以及同一用户只能有一份启用计划等不变量。
3. 单项替换后如何重新校验能量区间、时间冲突和恢复要求。
4. 计划与来源会话、健康档案版本、事实来源、候选资源的追溯关系。
5. LLM 输出失败或不满足规则时的重试、确定性降级和错误提示。

产出：领域模型、DDL 草案、接口、状态转换和页面所需 DTO。

## Answer

2026-08-10 已决策：

- 每周个人计划作为聚合根，包含每日作息、餐食项和训练项；每个计划保存来源会话、健康档案版本、事实来源和候选资源快照。
- 计划状态使用 `DRAFT / UNENABLED / ENABLED / HISTORY`，保留版本号、有效周和时区；同一匿名演示身份只允许一份 `ENABLED` 计划。
- 草稿确认后进入 `UNENABLED`，只有显式启用才进入 `ENABLED`；启用新计划时旧计划回到 `UNENABLED`，停用后才可转为 `HISTORY`。
- 项目批量保存统一处理新增、替换、删除、移动和训练处方调整；每次保存生成新版本，并重新执行能量区间、时间冲突、过敏、资格和训练恢复校验。
- LLM 输出失败或不满足规则时，优先重试一次，随后使用确定性降级或返回可解释错误，不持久化未经校验的计划。
- 健康档案更新不静默重算已激活计划；新计划使用新的健康档案版本，旧计划保留生成快照。

## 首版补充确认

- 用户编辑 ENABLED 计划时先复制为新的 DRAFT；编辑保存后的计划保持可编辑状态，用户需显式确认并启用，原计划保持稳定。
- 项目移动只改变日期/时间，备注可编辑；餐食营养事实只读，动作 duration/sets/reps 是服务端校验的计划处方。
- 资源替换由审核 Reader 提供资源事实；若同一批请求带有合法动作处方则保留该处方，否则按新资源的确定性默认值初始化。
