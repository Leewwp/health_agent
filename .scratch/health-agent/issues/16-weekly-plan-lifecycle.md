# 16 每周个人计划模型与生命周期

- Type: grilling
- Status: resolved
- Blocked by: 08, 09, 13, 14

## Question

每周个人计划如何建模、校验、持久化和局部调整，使它不是一段无法维护的 LLM JSON？

已确认交互下限：支持生成草稿、激活计划、历史版本，以及在草稿中移动已有项目的日期/时间和保存备注；第一版不做资源替换、自由编辑营养/训练剂量/作息规则或任意表格编辑。

待决策：

1. 计划聚合根、每日安排、餐食项、训练项、作息项和生成依据快照的关系。
2. `DRAFT / ACTIVE / ARCHIVED` 状态、版本号、有效周、时区，以及同一用户只能有一份活动计划等不变量。
3. 单项替换后如何重新校验能量区间、时间冲突和恢复要求。
4. 计划与来源会话、健康档案版本、事实来源、候选资源的追溯关系。
5. LLM 输出失败或不满足规则时的重试、确定性降级和错误提示。

产出：领域模型、DDL 草案、接口、状态转换和页面所需 DTO。

## Answer

2026-08-10 已决策：

- 每周个人计划作为聚合根，包含每日作息、餐食项和训练项；每个计划保存来源会话、健康档案版本、事实来源和候选资源快照。
- 计划状态使用 `DRAFT / ACTIVE / ARCHIVED`，保留版本号、有效周和时区；同一匿名演示身份只允许一份当前活动计划。
- 草稿确认后才能激活；激活新计划时旧活动计划归档。
- 单餐或单动作替换生成新版本，不直接覆盖历史版本；替换后重新执行能量区间、时间冲突、过敏和训练恢复校验。
- LLM 输出失败或不满足规则时，优先重试一次，随后使用确定性降级或返回可解释错误，不持久化未经校验的计划。
- 健康档案更新不静默重算已激活计划；新计划使用新的健康档案版本，旧计划保留生成快照。

## 首版补充确认

- 用户编辑 ACTIVE 计划时先复制为新的 DRAFT，确认后才生成新的 ACTIVE 版本；旧版本保留为历史快照。
- 拖拽只改变已有餐食、动作和作息项的日期/时间，备注可编辑；不改变资源本身的营养、训练剂量或作息规则。
- 首版不做餐食或动作资源替换；资源替换作为后续阶段。
