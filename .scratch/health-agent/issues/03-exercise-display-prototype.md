## Question

健身动作在页面中**如何展示**（Q5 遗留的"再确认健身动作在页面中的展示方式"）？用 /prototype 技能做一个可交互的静态 HTML 原型，验证三个交互面：

1. **动作浏览页**：卡片网格（GIF 缩略图 + 名称 + 部位/器材标签）+ 筛选器（部位/器材/训练目标）+ 分页或滚动加载——数据集的 1,324 动作全量可筛。
2. **对话内浮窗**：agent 在消息中推荐动作时，浮窗展示什么（名称、GIF、中文步骤、肌群、器材）、如何唤起、与消息气泡的布局关系。
3. **"喜欢/收藏"入口**：浏览页与浮窗里的收藏/喜欢按钮放在哪、收藏状态如何呈现。

原型还必须验证：媒体加载失败时的稳定布局、Gym visual 署名位置、全量浏览动作与“可进入计划的审核动作”如何区分，以及用户从计划页局部替换动作时是否复用同一详情交互。原型只决定交互，不决定前端框架和模块拆分；后者由已解决的 07 与 18 号票承接。

已确认事实：1,324 动作、每条含 GIF + 180×180 缩略图（远端 URL，需保留 Gym visual 署名）、10 部位 / 12 器材 / 目标肌群字段、中文步骤说明。展示密度与交互手感是本次验证重点（参照数据集自带的 index.html 浏览器做差异化）。

产出：可双击打开的原型文件，链接到本 ticket；原型结论（选择哪种展示形态、理由、对页面结构的影响）作为 Answer 记录。

### 原型结论

建议采用 **A 的动作浏览结构 + B 的详情抽屉 + C 的计划动作池分层**：

1. 浏览页使用左侧部位/器材/目标筛选，右侧紧凑卡片网格承载全量动作；卡片同时显示收藏、媒体署名和“入门候选 / 可浏览、可收藏”状态。
2. 对话推荐不展开大段步骤，消息中保留候选动作卡片；点击后打开统一右侧详情抽屉，展示 GIF、中文步骤、目标肌群、器材和计划资格。
3. 计划页按“日期容器 → 当日内容块 → 训练动作套组”分层；动作池提供入门候选、全量浏览和收藏动作三个入口。只有入门候选带拖拽柄并可拖入计划，其他动作仍可查看和收藏，计划资格在计划入口解释。套组内动作支持拖拽排序、调参数和移除，查看动作复用统一详情抽屉。

### 已验证交互

- A/B/C 通过底部切换条和 URL `?variant=` 切换，键盘左右方向键也可切换。
- 浏览页关键词筛选可更新结果；收藏可在浏览卡片、对话推荐、详情抽屉和已收藏列表之间保持内存状态。
- `deadlift` 使用故意失效媒体 URL，媒体失败后仍保留固定比例展示位、`© Gym visual` 署名和动作文字详情。
- C 变体入门候选示例为 7 条，全量池为 11 条，其中 4 条显示为“可浏览 / 可收藏”；它们仍可打开详情和收藏，但不显示拖拽柄，也不能直接拖入计划。收藏动作池可直接浏览已收藏动作；当前已收藏的入门候选可以拖入套组。
- C 变体按日期容纳餐饮、午休/作息和一个或多个训练套组；套组保留标题，折叠后仍显示动作数与总耗时。动作拖入折叠套组时立即展开，用户可以继续拖到具体动作位置再松开；成功放置后保持展开，未放置就离开套组或取消拖拽时恢复折叠。套组内动作拖拽可调整顺序，移除和调参数会重算套组总时长。
- 真实浏览器验证了收藏动作池、折叠套组自动展开、套组内排序、移除、调参数、详情抽屉与媒体失败降级；验证排序时修复了计划动作行缺少 `data-action-id` 导致拖拽处理提前返回的问题。
- 真实浏览器验证：桌面视口 `1710×983`、移动视口 `390×844`；页面无可见渲染错误，控制台事件无异常。仓库编译 `mvn -DskipTests compile` 通过。

### 实施阶段待定事项

3. 收藏是否作为跨页面即时偏好写入后端，还是只在用户主动“加入计划/采纳”后产生偏好事件。

## Comments

- 2026-08-10 用户反馈：浏览页大量“审核通过动作”和约束难以理解，倾向用“收藏”表达用户选择。
- 2026-08-10 原型迭代：收藏成为所有动作都可用的主入口；浏览层不再使用“审核”措辞。计划入口保留内部候选资格，只在计划整理和详情层解释“暂不作为入门候选”，避免把用户偏好误当作安全审核。
- 2026-08-10 用户补充：动作池应允许浏览收藏动作；一次训练由多个动作组成，需要展示整套总耗时，并能调整动作、组数、次数和组间休息。
- 2026-08-10 原型迭代：C 变体新增“收藏动作”池；计划按“下肢基础套组 / 胸部力量套组 / 全身收尾套组”展示，每套显示动作数和预计总分钟数，每个动作显示组数、次数和组间休息。支持调参数后重算总时长、从动作池拖拽候选动作加入套组，并通过移除动作完成整理。
- 2026-08-10 用户补充：拖拽进入折叠套组时应自动展开，用户可继续拖到具体动作位置；未松开鼠标就离开目标套组时，应恢复折叠。
- 2026-08-10 原型迭代：拖拽状态增加“本次拖拽自动展开的套组”记录。进入折叠套组立即展开，移动到内部动作时保持展开；成功放置后保留展开，离开未放置或触发拖拽结束取消时恢复折叠。
- 2026-08-10 用户确认：保留当前原型设计并将其作为后续前端实现与浏览器验收的交互参考。
