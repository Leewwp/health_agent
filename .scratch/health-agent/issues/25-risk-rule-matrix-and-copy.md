# 25 健康风险规则矩阵与用户文案

- Type: grilling
- Status: resolved
- Blocked by: 14, 19, 20

## Question

将三档风险策略落成带编号和版本的规则矩阵：饮食过敏/禁忌、极端摄入、伤病与孕产、训练过量、作息冲突、医疗转介等条件分别在哪一层命中，如何组合多个命中，何时拒绝具体计划，何时允许一般建议并附提示？

需要同时冻结用户可见中文文案、来源/免责声明展示、规则命中与误拦截/漏拦截的 Trace 字段，以及一组可复现的正例、边界例和降级例。目标是让候选过滤器、计划组合器和 LLM 输出校验器共享同一套规则语义。

## Answer

2026-08-10 已按“面试展示项目的最小实现”确认：

- 风险结果只保留三档：`NORMAL`、`ADVISORY`、`BLOCK_PLAN`；多个规则同时命中时取最高等级。
- 候选前过滤明显的过敏、禁忌和不具备 `plan_ready` 的资源；计划组合时校验能量区间、时间冲突、训练部位连续安排和资源资格；LLM 输出后校验结构、资源 ID、数值、来源和风险文案。
- 以下情况拒绝生成具体计划：胸痛/眩晕/活动相关疼痛、当前伤病/术后/康复、孕产、进食障碍或需要医疗干预的慢性病、诊断治疗药物请求、明确极端节食/快速减重诉求、未满 18 岁，以及 65 岁以上的具体训练计划请求。过敏优先过滤资源，过滤后无候选再降级。
- 首版具体训练计划范围为 18-64 岁的一般健康成年人；超出范围仍可返回一般性信息或固定提示，不进入训练计划组合器。
- 不为首版引入来源不足的复杂医学阈值。只拒绝明确极端诉求、LLM 越过确定性计算区间、计划硬冲突和规则边界的结果；能量上下限沿用 24 号量化目标契约。
- 用户文案使用固定中文模板。来源、规则版本和“估算值”由结构化字段展示，不由 Agent 自由生成；风险提示不宣称诊断、治疗或绝对安全。
- Trace 复用现有 `diet_request_trace.trace_json`，记录 `ruleCode`、`ruleVersion`、`stage`、`severity`、`decision`、必要时的 `resourceId` 和 `fallbackType`；不新增独立风险规则表、风险后台或用户安全管理页面。

### 最小实现边界

1. 使用一个 `RiskRuleService` 和少量版本化规则常量/枚举，不实现可配置规则平台、医学知识库或安全分类模型。
2. 三个阶段只要求有可调用的确定性校验方法，不要求拆成复杂的规则引擎、工作流或外部审核服务。
3. 只准备核心正例、边界例、拒绝例、空候选和 LLM 越界样例，用于自动化冒烟；不投入大规模误拦截/漏拦截研究、专业人员审核流程或长期安全运营。
4. 规则的价值是展示“LLM 不拥有最终安全决定权”和“失败可降级”，不是宣称本项目具备真实医疗安全能力。
