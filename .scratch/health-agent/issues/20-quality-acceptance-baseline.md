# 20 检索、计划与降级质量验收基线

- Type: grilling
- Status: resolved
- Blocked by: 10, 16, 19

## Question

如何定义“项目完成”，使 RAG、周计划和多品类对话可以用可复现指标验证，而不是只靠几次演示感觉正确？

待决策：

1. 意图/slot 基准集与状态机关键场景覆盖。
2. 混合检索的 Recall@K、结构化约束命中率、无 embedding 降级正确率。
3. 周计划能量区间、时间冲突、资源引用、风险规则和局部替换后的不变量。
4. LLM JSON 非法、DashScope 超时、Redis/MySQL 不可用、媒体 404 时的预期行为。
5. 冒烟链路、Testcontainers 范围、浏览器验收和部署后健康检查。

产出：验收矩阵、最小测试数据集、必须自动化的核心测试与可手工冒烟项。

## Answer

2026-08-10 已决策：采用“核心自动化测试 + 其他接口和页面冒烟验收”的质量基线。

- 自动化覆盖多品类意图、槽位合并、编排路由、周计划不变量、局部替换、风险规则和餐食混合检索。
- 餐食混合检索比较 structured-only 与 hybrid 的 Recall@K、硬约束命中率和 Embedding 失败降级；没有可复现提升时不把 RAG 作为成果。
- 指南证据检索增加引用相关性、来源完整性、适用人群匹配和无证据时的安全降级验收。
- 计划测试覆盖能量区间、时间冲突、资源引用、风险规则、版本快照和替换后的不变量。
- 失败场景覆盖 LLM 非法 JSON、DashScope 超时、MySQL/Redis 不可用、Embedding 失败和媒体 404。
- 其他 API、页面、计划激活和部署健康检查通过真实浏览器和部署后冒烟链路验收。
- 最小测试数据集使用可复现的固定餐食、动作、作息事实、指南片段和 Embedding 测试 adapter，不依赖在线 LLM 才能运行核心测试。
