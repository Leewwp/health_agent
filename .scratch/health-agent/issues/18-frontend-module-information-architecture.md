# 18 前端模块边界与页面信息架构

- Type: grilling
- Status: resolved
- Blocked by: 03, 07, 16, 17

## Question

在不引入 Node/Vite/Vue/React 的前提下，如何把现有千行 `app.js` 拆成可维护的原生 ES Modules，并统一餐食、动作、计划和对话内详情交互？

已确认方向：保留 hash 路由；按 `router`、`api`、`store`、各页面模块和共享 UI 拆分；不保留 static/frontend 双副本。

待决策：

1. 页面导航、路由懒加载与共享状态最小接口。
2. 对话推荐卡片点击后使用详情抽屉/模态层，还是直接展开；“浮窗”统一成哪一个精确术语。
3. 餐食无图片、动作 GIF 加载失败、网络慢和空数据时的降级状态。
4. 收藏、局部替换、计划激活和来源引用的交互反馈。
5. admin 页面是否保留在同一前端入口，还是构建时/路由级隔离。

产出：目录结构、页面信息架构、共享 UI 接口和浏览器验收场景。

## Answer

2026-08-10 已按“满足项目需求的最小实现”确认：

- 前端继续使用 vanilla hash 路由和原生 ES Modules，按 `router`、`api`、`store`、`ui`、`pages`、`admin` 拆分。页面通过原生 `import()` 按路由加载，不引入 Node/Vite/Vue/React、路由库或状态管理库。
- 用户页面保持统一入口，新增餐食、动作和周计划页面；现有 `/diet` hash 路由保留为兼容入口，新页面使用健康领域路由命名。用户侧导航不展示 Trace、评估和导入入口。
- 共享状态只保留匿名会话摘要、按类型化资源身份索引的收藏状态和当前计划摘要。页面数据仍由各页面按需请求，不建立万能全局 Store。
- 所有餐食、动作、对话推荐和计划资源详情统一称为“详情抽屉”：桌面端从右侧打开，移动端占满屏幕；详情内容通过资源类型分派，收藏控件复用同一接口。
- 资源列表统一提供加载占位、空结果、接口失败重试和媒体失败占位。媒体失败不得改变卡片尺寸；动作详情保留 `Gym visual` 署名，餐食无图片时显示稳定的无图状态。
- 收藏采用乐观更新，失败时回滚；喜欢、不喜欢和采纳提交后显示轻量反馈。ACTIVE 计划编辑先复制为 DRAFT，激活计划需要确认；来源和计算依据使用结构化详情展示。
- Trace、评估和导入页面保留在前端代码中但置于 admin 路由，生产环境由后端禁用或鉴权，开发环境才允许访问。不能只依赖隐藏导航实现隔离。

### 浏览器验收场景

1. 桌面端和 `390×844` 移动端均可在聊天、餐食、动作和计划页面之间切换，无横向溢出。
2. 对话推荐、动作卡片和计划资源打开同一个详情抽屉；收藏状态在不同入口保持一致。
3. 接口慢、接口失败、无结果、餐食无图和动作媒体 404 时，页面布局稳定且能重试。
4. 用户侧无法通过导航或直接 hash 访问 admin 功能；开发环境 admin 页面仍可完成 Trace/评估冒烟。

### 实施约束

1. 生产迁移到独立 `frontend/` 后删除 `src/main/resources/static/` 双副本；本票只冻结目录和行为，不在此票中迁移代码。
2. 详情抽屉只展示后端返回的资源字段、来源和校验结果，不在前端或 Agent 中重新推导营养、训练剂量和风险结论。
3. 18 号只冻结前端承载方式；最终 API、DTO 和资源字段由 22、26 号票据收敛。
