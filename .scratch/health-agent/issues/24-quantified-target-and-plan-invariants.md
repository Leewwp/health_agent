# 24 量化目标与周计划不变量契约

- Type: grilling
- Status: resolved
- Blocked by: 13, 14, 16

## Question

把“确定性量化目标”和“计划校验”从原则收敛为可计算契约：Mifflin-St Jeor 的输入缺失分支、生理性别缺失时的区间、活动系数、目标调整、舍入、上下限、营养口径和估算标记如何定义？

同时冻结周计划的七天时区、日程边界、作息/训练/餐食冲突、恢复间隔、能量区间、档案版本快照、DRAFT/ACTIVE/ARCHIVED 转换，以及编辑后何时标记过期。每条规则都要说明失败时是拒绝、提示还是降级，避免由 LLM 自由补数值或补计划。

## Answer

2026-08-10 已按“满足项目需求的最小实现”确认：

- 健康档案必填年龄、身高、体重、活动水平和主要目标；生理性别、时区、典型作息、训练经验、可用器材、饮食禁忌和伤病限制为选填。生理性别缺失时不由 LLM 猜测，使用两种公式结果形成更宽的估算区间。
- 基础能量使用 Mifflin-St Jeor：男性 `10W + 6.25H - 5A + 5`，女性 `10W + 6.25H - 5A - 161`，其中 `W` 为千克、`H` 为厘米、`A` 为年龄；再乘活动系数得到日常能量估算。
- 活动系数首版只保留 `1.2`、`1.375`、`1.55` 三档。目标调整使用保守区间：维持 `±5%`、减脂 `-5%~-15%`、增重 `+5%~+10%`。结果四舍五入到 50 kcal，并明确标记为估算值，不作为医疗处方。
- 首版只计算每日能量区间，不计算碳水、脂肪等复杂宏量营养目标；LLM 不得补写未计算的营养数字。能量安全上下限和风险拒绝阈值由 25 号风险矩阵统一定义。
- 周计划使用用户时区，缺省 `Asia/Shanghai`；一周按本地时间周一至周日。计划项目保存本地日期、开始时间、结束时间和时区，不能使用服务器时区隐式解释。
- 同一匿名用户只能有一份 ACTIVE 计划。作息和训练时间不得互相重叠；同一训练部位默认不安排连续两天；餐食只校验时间窗口和日能量区间，首版不强制复杂的餐训间隔。
- DRAFT 可编辑和保存；硬错误禁止保存或激活，警告允许保存 DRAFT 但不能直接激活，正常结果允许继续。ACTIVE 编辑先复制为新的 DRAFT，校验通过后再激活新版本。
- LLM 计划解释输出失败或结构不合格时不重试，立即使用确定性模板或返回可解释错误；计划组合本身由 Java 确定性服务完成，未经确定性校验的计划不得持久化或激活。
- 健康档案更新后不自动重算已激活计划；已激活计划保留生成时的档案版本和数值快照，并标记“档案版本较旧，需要重新确认”。新计划使用最新档案版本。

### 校验结果分类

```text
HARD_ERROR  -> 拒绝保存/激活
WARNING     -> 可保存 DRAFT，不可激活
OK          -> 可继续流程
DEGRADED    -> 使用确定性模板或返回信息不足
```

### 实施约束

1. 公式、活动系数、目标调整、舍入和档案版本必须由 Java 确定性服务计算，不能放进 Prompt 让模型执行。
2. 计划组合器只消费已计算的能量区间、已确认的资源和已版本化的事实；Agent 只能解释结果。
3. 25 号票据负责补齐能量上下限、极端目标、伤病和风险转介阈值，不能在其他模块另行定义。
4. 所有计划校验失败必须写入 Trace，包含规则编号、版本和 `HARD_ERROR/WARNING/DEGRADED` 结果。
