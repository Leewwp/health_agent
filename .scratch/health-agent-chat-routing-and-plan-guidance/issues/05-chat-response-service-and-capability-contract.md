# 05: 独立 CHAT 回答服务与能力问句契约

**What to build:** 新增专用 CHAT 回答服务与提示词：以“健康助手”身份介绍能力（餐食/动作推荐、餐食/训练/综合周计划、作息建议），说明下一步可说的自然语言，回答一般健康常识问题；明确声明支持推荐与计划制定，避免“我只是聊天助手，不能帮你制定计划或推荐”的矛盾回答。不检索餐食/动作资源、不生成/修改计划、不做医疗诊断或治疗承诺；既有风险规则目录与风险服务继续在 CHAT 输出前评估与拦截。确定性降级路径提供能力介绍固定文案。`taskFocus`/`domain`/`side` 类伪槽位 key 不再进入 missingSlots 渲染通道，澄清选项以后端下发的结构化 action 表达（携带领域/任务语义，点击即合法任务证据）。

**Blocked by:** None (can start immediately)

**Status:** resolved（2026-08-31 实施完成：`HealthChatAnswerService` + `diet/prompts/health-chat.txt`（身份/能力/常识，声明支持推荐与计划、不做诊断治疗）；编排器 CHAT 通道接入并保留确定性降级文案；taskFocus 澄清改为四个 `SELECT_TASK` 结构化动作（点击发送携带任务证据的短语）；合同测试 `HealthChatAnswerServiceTest`；浏览器验收：真实模型 CHAT 回答符合边界，SELECT_TASK 点击链路正常）

- [ ] 全新会话问“你是谁？能帮我做什么”/“你能帮我做什么” → 健康助手身份 + 支持能力清单 + 下一步自然语言示例，不出现僵硬的任务澄清
- [ ] 普通健康常识问题（无任务关键词）得到 CHAT 回答，不出现推荐卡片、不调用资源检索、不变更计划简报
- [ ] CHAT 回答明确声明支持推荐与计划制定（用户问“你能帮我制定计划吗”不会得到“不能”）
- [ ] 风险问题（急症/用药/治疗）仍被既有风险规则拦截或提示就医，CHAT Agent 不做不安全医疗表述
- [ ] CHAT 响应服务合同测试：合法 JSON、畸形输出确定性降级、能力措辞、无资源约束、风险安全措辞
- [ ] 伪槽位 key（taskFocus 等）不再渲染为“其他偏好”类误导标签；澄清选项为结构化 action，点击构成合法任务证据
- [ ] 降级模式（模型不可用）能力问句得到固定能力介绍文案
- [ ] 既有 `OTHER + CHAT` 相关测试更新并注明理由
