# 03: 澄清继承保真与续轮继承边界（RC-2/RC-3/RC-4）

**What to build:** 推荐域澄清续轮不再零条件继承陈旧会话状态：只有本轮输入解析出待澄清字段值、或命中共享任务证据词表时才继承上下文；显式聊天/能力问句（“能陪我聊天吗”“你是谁”“你能帮我做什么”）必须打断继承进入 `OTHER + CHAT`。澄清继承在任何路径上都保持 `state.task()`，禁止把 `PLAN` 覆写为 `RECOMMEND/ADJUST`（推荐式任务改写仅在原任务本就是 RECOMMEND/ADJUST 时成立）。澄清挂起状态设时效边界（跨会话日期或超过既定轮数后失效）。澄清/能力问句响应不再继承展示旧 domain/task 标签。继承不豁免最终闸门（闸门本身在 04 号票据实现，本票据保证继承判定产出可被闸门复核的来源标记）。

**Blocked by:** 02（继承条件与逃生表达消费共享词表）

**Status:** resolved（2026-08-31 实施完成：`clarifyContinuationJustified` 单一实现（continueBeforeAgent/revise 共用）——聊天逃生打断、`clarifyEpoch` 跨天失效、字段值或任务证据才允许继承；继承保真 `task = state.task()` 禁止 PLAN→RECOMMEND 覆写；澄清日期戳持久化于会话 `_meta`；能力问句/仲裁失败澄清响应标签改 OTHER+CHAT、伪槽位 key 出清；最小聊天回归与时效回归落地；浏览器验收：“能陪我聊天吗”“你能帮我做什么”在真实模型下均 CHAT 且零资源卡）

- [ ] 最小聊天回归（RC-3 直接复现）：会话状态 `(MEAL, ADJUST, CLARIFY)` + 输入“能陪我聊天吗” → 不调用餐食检索、无资源块、响应为 CHAT；`(EXERCISE, RECOMMEND, CLARIFY)` 同型用例通过
- [ ] PLAN 澄清状态下的短答不得被改写为 `RECOMMEND/ADJUST`（RC-2 直接回归；含“新建 vs 修改”澄清后回答不含修改/新建词落通用链的残余入口）
- [ ] 合法澄清短答（“增肌”“清淡一点”等待澄清字段值）仍正常继承并推进收集，不因收紧而误伤
- [ ] 陈旧澄清状态（跨会话日期/超过既定轮数）不再被继承，按新输入正常路由
- [ ] 能力问句（“你能帮我做什么”）的澄清/回答响应不携带陈旧 domain/task 标签；仲裁低置信澄清不再把旧域标签固化展示给用户
- [ ] “能陪我聊天吗”在推荐后、计划澄清后、仲裁尝试后、生成计划响应后四个上下文中都保持 CHAT（P0 哨兵）
- [ ] Trace 记录澄清继承判定（继承/打断）与原因，可诊断
- [ ] 既有 ADR-0018 路由/仲裁测试保持通过；行为变化条目注明替代决策
