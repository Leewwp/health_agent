# 04: 最终任务闸门（RC-5，封堵模型单独启动任务）

**What to build:** 在所有确定性路由与模型/仲裁修正之后、任何资源检索或计划处理器之前，增加统一最终任务闸门：当前轮必须存在“可执行证据”——共享硬证据词表命中、活跃 `PLAN + OPEN` 续轮且字段值可解析、结构化动作证据（`alternative` payload、后端下发的澄清/任务动作点击、推荐预检挂起 + 确认短语）、或本轮实际调用的意图/仲裁模型与确定性判定 domain+task 双一致。前三类单独即可执行（保留 ADR-0018 确定性直路由与无模型降级能力）；**模型单独判定（无任何确定性证据）不得启动任务**，降级为 CHAT 或澄清；模型与确定性判定不一致或低置信时澄清不执行。无模型轮（快路径、续轮、降级）以确定性判定 + 最终闸门替代双一致。仲裁 authoritative 路径同样受闸门复核（封堵“能陪我聊天吗”被模型判成餐食推荐的残余入口）。

**Blocked by:** 01, 02, 03（闸门的续轮/继承证据口径由前三票建立）

**Status:** resolved（2026-08-31 实施完成：`hasExecutableTaskEvidence` 五类白名单（词表/计划词/调整词/推荐动词、简报解析器续轮、结构化动作（alternative/预检确认/澄清消费）、作息事实问答、经边界与时效复核的澄清继承）；闸门紧贴 handleRecommend 分派前并记录 `FINAL_TASK_GATE` trace 事件；`CHAT_ESCAPE` 快路径不消耗仲裁预算；无模型轮以确定性证据替代双一致（降级模式回归兼容）。浏览器验收发现并修复：真实仲裁低置信曾把预检确认“开始推荐”劫持成任务澄清——确认短语提升为模型链之前的结构化证据（`PREFLIGHT_CONFIRMATION`））

- [ ] 仲裁返回高置信 `MEAL + RECOMMEND` 但当前轮无任何确定性证据（输入“能陪我聊天吗”）→ 不检索、降级 CHAT/澄清（RC-5 回归）
- [ ] 硬证据单独（无模型降级模式）仍执行：快捷问题与同义自由输入（“给我推荐一份餐食”“给我推荐一个训练动作”）在模型不可用时正常触发推荐
- [ ] 硬证据 + 模型一致 → 执行；硬证据 + 模型不一致（领域或任务任一不齐）→ 澄清不执行；低置信/模型失败 → 澄清不执行
- [ ] 白名单回归：`alternative` payload（换一批）、预检确认短语（“开始推荐”）、`PLAN + OPEN` 字段续轮（“周一到周三”）在无模型时均执行
- [ ] 闸门位于编排器最终分派前，覆盖所有 `RECOMMEND/PLAN/ADJUST/ROUTINE` 执行入口（含推荐主链与附加动作试探检索），无绕过路径
- [ ] Trace 记录硬证据结果、模型一致性结果、最终闸门决定与降级原因（在既有 raw/revised intent 与仲裁来源之上）
- [ ] 被拒模型推荐的 Trace 检查用例：能证明“硬证据缺失 + 最终 CHAT 决定”被记录，未来回归可诊断
- [ ] 既有预检/换一批/additionActions 契约行为不变（仅纳入白名单语义，不重构）
