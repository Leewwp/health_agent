# 02: 共享硬证据词表唯一所有者与漂移守卫（RC-7，prefactor）

**What to build:** 建立“当前轮任务硬证据”的统一词表与判定接缝，由 routing/intent 层的共享判定单一拥有；把现存的四处漂移副本（意图规则服务的 adjust 词表、意图修订服务的 adjust 词表、编排器私有确认短语与追加词表、共享判定的推荐词表、任务证据词表）收编为同一来源；审计并收窄任务证据中的过宽裸字（如“菜”“餐”），全量回归确认收窄无破坏；聊天/能力逃生词定位为结构化条件下的短路优化归同一所有者维护，不构成独立关键词例外清单（与 ADR-0018 一致）。新增词表漂移守卫测试，防止未来修改再次分叉。

**Blocked by:** None (can start immediately)

**Status:** resolved（2026-08-31 实施完成：`HealthTaskEvidence` 扩展为唯一所有者——adjust/确认短语/追加词/聊天逃生/推荐请求动词；`IntentRuleService` 兜底与 `HealthIntentRevisionService.revise` 消费共享清单，作息组合证据经 `HealthBriefRouter.domainEvidence`/`IntentRuleService` 消费同一判定；“练”补入活动词、“餐食”补入口语信号；漂移守卫测试 `TaskEvidenceVocabularyDriftGuardTest` 固定口径。审计结论：MEAL_TASK_WORDS 过宽裸字“菜/餐”经评估保留——模型轮需与确定性证据一致才执行，单独裸字不构成执行）

- [ ] 意图规则服务与意图修订服务消费同一 adjust 词表；“换一批”“再来一批”等替换行为口径一致
- [ ] 编排器的推荐确认短语（“开始推荐”等）与“追加到当前计划”词表改由共享所有者提供，行为不变
- [ ] 任务证据词表过宽裸字（“菜”“餐”等单字命中）收窄后，既有快捷问题与同义自由输入（“给我推荐一份餐食”）仍正常触发，无关聊天不触发
- [ ] 聊天/能力逃生表达（“能陪我聊天吗”“你是谁”“你能帮我做什么”等）进入共享词表并由同一所有者维护，可被路由判定与闸门共同消费
- [ ] 新增漂移守卫测试：任何新增任务词/逃生词必须落在共享所有者，逐副本一致性由测试固定
- [ ] 全量测试通过，health-eval-v2 快照中受收窄影响的条目更新并注明理由

**规范来源:** spec.md「Implementation Decisions · 任务入口与闸门」共享硬证据词表唯一所有者条、Testing Decisions 词表漂移守卫。
